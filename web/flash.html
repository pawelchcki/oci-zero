Open a firmware artifact

An OCI layout tar, as attached to the rolling firmware release. Nothing is uploaded and nothing is fetched: the archive is walked in this tab by the same oci-zero build the registry browser uses.

Or produce one yourself:
crane pull --format=oci ghcr.io/pawelchcki/oci-zero-firmware:latest layout
tar -cf firmware.oci.tar -C layout .

Device

Leave this on unless you are keeping a commissioned device on its fabric. The artifact writes a partition table, and anything the board's previous table left behind at the new otadata or nvs offsets is read as if this firmware had written it — which can boot an empty slot, or convince the firmware it is already commissioned so it never advertises.

What is verified. is the SHA-256 of the file you picked, computed here — it proves nothing on its own, and neither does index.json, the root of the archive. Everything below it is verified: the manifest against the descriptor in index.json, and the config and layer against the descriptors in the manifest, with the layer hashed by oci-zero as it inflates. Compare the manifest digest above against crane digest ghcr.io/pawelchcki/oci-zero-firmware:latest to tie the archive back to the registry.
